# Analytics (`clave.analytics`)

A bundled plugin that measures the Claude Code sessions Clave shows: what each one cost at list prices, how long it was active, the tokens it read and wrote, its tool calls and prompts, per session, per group and per workspace.

The data comes from the transcripts on disk. A Claude tab (`claude`, `claude-agents`) with a provider session id reads `~/.claude/projects/<slug>/<id>.jsonl`, where the slug is the cwd with every character that is not a letter or a digit replaced by `-`. Its subagents read `<id>/subagents/agent-<n>.jsonl` with their `.meta.json` beside them. Files are read incrementally, from a byte offset. One streamed assistant message is written once per content block, and each row repeats the same `usage`, so usage is counted once per message id. Tool calls are counted by distinct `tool_use` id. `<synthetic>` rows count nothing. A prompt is a user row a person typed (no tool result, no harness injection, no sidechain).

The data folder (`CLAVE_PLUGIN_DATA_DIR`, else `clave-analytics` under the temp folder) holds `ledger.json` (one row per session with its tallies, file cursors and state spans), `server.json` (port, URL token and the viewer's port), the `decks/` folders (below) and, optionally, `prices.json`, an override of the shipped `prices.json` (USD per million tokens). Models without a price are reported as unpriced and never guessed.

The server listens on 127.0.0.1 only. Every route sits under `/<token>/`: `session/<id>`, `group/<id>` and `workspace?ws=<id>` (pages, with `range=today|7d|30d|all` and `theme=`), `data/session/<id>.json`, `data/group/<id>.json` and `data/workspace.json` (the same views as JSON), `events?scope=...` (server-sent `data` events on every change), `assets/deck.css|deck.js` and the `open/...` routes (below). Anything else answers an empty 404. The `deck` action (session, group) and the `home` action (workspace) answer the `open` URLs, and `deck` also answers a six-row preview.

The pages are built by `scripts/build-plugins.mjs`: `src/main.ts` → `main.mjs`, `page/deck.ts` → `dist/deck.js`, and `dist/deck.css` = embedded Geist Sans + `packages/ui/src/tokens.css` + `page/deck.css`. `electron-vite dev` and `build` run it, and so does `npm run plugins:build`. The outputs are git-ignored.

What the pages draw, live. The figures and the tables of the first slice; on the session page a timeline of its activity blocks on the wall clock (hover a block for its minutes, messages and tool calls a minute, a gap for the wait), on the group page a swimlane of its sessions' blocks on one wall clock with each session's state dot, and on the workspace home one calm animation of what happens now: every live session a dot in its group's lane, at the column of its state (working, idle, needs you), moving when the host's session list says so, on the brand field as the home's ground (the renderer's own engine, lifted toward the app's surface, never faded). The pure half (the time scale, the lanes, the waits) is `packages/analytics/src/timeline.ts`; the ground is `page/field.ts`, the animation `page/live.ts`. The pages' shape (the hero with the page's drawing, the count tiles, the section labels, the cards) is the design-deck skill's (`plugin/skills/design-deck`), the same as the routine report's; the three drawings in the hero (`page/drawings/*.svg`, their markup in `page/drawings.ts`, `packages/analytics/src/drawings.test.ts` keeping the two equal) are made with that skill's hand: the workspace's groups as lanes with a session moving to needs-you, a group's sessions on one clock with now down the clock, a session's blocks with the cost rising.

The settings page, `/settings` under the token, reached from the pages' footer gear: the activity gap (the minutes a silence must reach to end a block, 15 by default, kept in `settings.json`) and the price table, editable row by row, written as the override `prices.json` with its date, the shipped table the fallback a button brings back. A saved gap or table reaches every open page through the live stream.

The pages as Slideless decks, on this Mac. Slideless is the renderer here, never a destination: nothing is pushed, no account is used, nothing leaves the Mac. Every page a person opens is written as a deck folder under `decks/` in the data folder, `session-<id>`, `group-<id>-<range>` or `workspace-<ws>-<range>`, holding `index.html` (the page itself, self-contained: the stylesheet and the script inlined, the scope's data in its `slideless-data` block, the plugin's stream named absolute), `data.json` (the same view) and `AGENT.md` (what the deck is, as Slideless templates carry); the root holds its own `index.html` naming the folders. The plugin runs one `slideless dev <decks> --port <n> --no-open --json` child over that root, the CLI's own local viewer (every file under the root on loopback, a reload snippet in every page, a reload broadcast when anything under the root changes, the viewer's sandbox headers), spawned as an argument list with the login shell's environment: the CLI is found on the plugin's own path first and on the login shell's path second (`/bin/zsh -lic`, the way the app finds `gh`; the shell prints a mark before its environment so a profile that prints a line cannot hide the path, the shell is resolved once per plugin process and again after the CLI was found missing, and a shell that hangs is killed at 15 seconds). The viewer's port is read from the CLI's JSON line and kept in `server.json` (`viewerPort`) so the next start asks for the same one (any port when that one is taken); a viewer that exits is started again with a backoff; `deactivate` stops it. The host's actions and every link on a page (the range chips, the workspace's cards, the footer's gear) lead through the plugin server's `open` routes (`open/session/<id>`, `open/group/<id>?range=`, `open/workspace?ws=&range=`): an open writes the scope's deck now and answers a redirect to the viewer's copy, `http://127.0.0.1:<viewerPort>/<folder>/index.html`, whose footer ends with `Served by the Slideless viewer on this Mac`; every deck opened in this process is rewritten, debounced like the ledger's own write, whenever its view changes, so the folder on disk is the page as it stands. The viewer's copy follows the ledger live the way the plugin's own page does, through the plugin's stream named absolute in the deck (`analytics-events`): the viewer's sandbox header gives its pages an opaque origin, so the `events` and `data` routes answer any origin (`access-control-allow-origin: *`, the token in the path the guard, nothing under it writing on a GET), and the viewer's own reload stream, refused by that same sandbox in the CLI as installed (0.13.12: no CORS answer on `/__slideless/reload`), is not what a deck relies on; when it works, a rewrite reloads the page as well. Inside Clave the page pane injects the app's theme into the deck as into any page; in a browser the system scheme applies. Without the CLI, the page Clave serves itself is the fallback, its footer saying why in one line (`The Slideless CLI is not on the login shell's path: run team tools install slideless to see this page through its viewer`, or the start's own first line), and an open waits at most five seconds for a viewer still starting before it falls back. A deck folder is the person's: `slideless push <folder>` on their own login puts it on Slideless if they ever want, and the plugin never does.

Not yet here: the Codex and Pi readers (`PRDCT-4031`); a tab of those providers gets a row with no transcript.

The pages set their root at the control text size (`html, body { font-size: var(--control-text) }`), so every house token resolves one size down from the app's own (a 28 px control is 22.75 px here), the way a frame's controls do; the sizes stay tokens, and the sheet is one scale, chosen with the first slice and kept.

Tests: `npx vitest run packages/analytics`; types: `npm run typecheck:plugins`.
