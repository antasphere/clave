# Analytics (`clave.analytics`)

A bundled plugin that measures the Claude Code sessions Clave shows: what each one cost at list prices, how long it was active, the tokens it read and wrote, its tool calls and prompts, per session, per group and per workspace.

The data comes from the transcripts on disk. A Claude tab (`claude`, `claude-agents`) with a provider session id reads `~/.claude/projects/<slug>/<id>.jsonl`, where the slug is the cwd with every character that is not a letter or a digit replaced by `-`. Its subagents read `<id>/subagents/agent-<n>.jsonl` with their `.meta.json` beside them. Files are read incrementally, from a byte offset. One streamed assistant message is written once per content block, and each row repeats the same `usage`, so usage is counted once per message id. Tool calls are counted by distinct `tool_use` id. `<synthetic>` rows count nothing. A prompt is a user row a person typed (no tool result, no harness injection, no sidechain).

The data folder (`CLAVE_PLUGIN_DATA_DIR`, else `clave-analytics` under the temp folder) holds `ledger.json` (one row per session with its tallies, file cursors and state spans), `server.json` (port and URL token) and, optionally, `prices.json`, an override of the shipped `prices.json` (USD per million tokens). Models without a price are reported as unpriced and never guessed.

The server listens on 127.0.0.1 only. Every route sits under `/<token>/`: `session/<id>`, `group/<id>` and `workspace?ws=<id>` (pages, with `range=today|7d|30d|all` and `theme=`), `data/session/<id>.json`, `data/group/<id>.json` and `data/workspace.json` (the same views as JSON), `events?scope=...` (server-sent `data` events on every change) and `assets/deck.css|deck.js`. Anything else answers an empty 404. The `deck` action (session, group) and the `home` action (workspace) answer those page URLs, and `deck` also answers a six-row preview.

The pages are built by `scripts/build-plugins.mjs`: `src/main.ts` → `main.mjs`, `page/deck.ts` → `dist/deck.js`, and `dist/deck.css` = embedded Geist Sans + `packages/ui/src/tokens.css` + `page/deck.css`. `electron-vite dev` and `build` run it, and so does `npm run plugins:build`. The outputs are git-ignored.

What the pages draw, live. The figures and the tables of the first slice; on the session page a timeline of its activity blocks on the wall clock (hover a block for its minutes, messages and tool calls a minute, a gap for the wait), on the group page a swimlane of its sessions' blocks on one wall clock with each session's state dot, and on the workspace home one calm animation of what happens now: every live session a dot in its group's lane, at the column of its state (working, idle, needs you), moving when the host's session list says so, on the brand field as the home's ground (the renderer's own engine, lifted toward the app's surface, never faded). The pure half (the time scale, the lanes, the waits) is `src/timeline.ts`; the ground is `page/field.ts`, the animation `page/live.ts`.

The settings page, `/settings` under the token, reached from the pages' footer gear: the activity gap (the minutes a silence must reach to end a block, 15 by default, kept in `settings.json`) and the price table, editable row by row, written as the override `prices.json` with its date, the shipped table the fallback a button brings back. A saved gap or table reaches every open page through the live stream.

Publish, in every page's footer: the page itself, pushed to Slideless as a deck of its own with the person's own `slideless` CLI on their own login. The deck is one self-contained file (the stylesheet and the script inlined, the page's live token values written in so it wears the app's theme as it was, the data in its block, the stream off, the chips and the links gone), written under `decks/` in the data folder and pushed with the CLI's arguments as a list (`push <folder> --json --no-open --title … --new` the first time, `push <folder> --json --no-open --id <deck>` after, so the share links stay). The CLI is found on the plugin's own path first and on the login shell's path second (`/bin/zsh -lic`, the way the app finds `gh`), and `whoami` runs before anything is written or sent: a CLI missing from the path, or not signed in, is one sentence on the page with the command to run. The data pushed is the scope's aggregated view, the session names and folders redacted to `Session n` unless the box is ticked at publish time, never a prompt, never a transcript line; what was pushed is kept beside the ledger as `published/<scope>-<n>.json`, and the deck each scope was published as in the ledger itself. Nothing goes into anyone's workspace templates and no data-bound document is made; the deck's metadata, annotations and links are the person's to edit on Slideless.

Not yet here: the Codex and Pi readers (`PRDCT-4031`); a tab of those providers gets a row with no transcript.

Tests: `npx vitest run plugins/analytics`; types: `npm run typecheck:plugins`.
